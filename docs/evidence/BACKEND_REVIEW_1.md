# Backend adversarial review #1: Scaffold primary entry

- **Date:** 2026-10-17
- **Scope:** `src/core/*`, `src/demo/seed.ts`, `src/store/*`, `src/server/*`, `infra/template.yaml`, `tests/*`. `src/apps` and `src/web` were out of scope and were not touched.
- **Method:** I read every file in scope. I probed the running Express app over real sockets, drove the Lambda handler through `serverless-http` with a mocked DynamoDB client, and read the code paths inside the MCP SDK 2.3.1, `@modelcontextprotocol/node` and `serverless-http`.
- **Evidence:** every finding below has a test that fails today, in `primary-entry/tests/review/*.test.ts`. The test names carry the finding id.

Run the failing tests with:

```
cd primary-entry && npx vitest run tests/review
```

The result is 35 failing tests across 4 files. The existing suite still passes: `npx vitest run tests --exclude 'tests/review/**'` gives 43 passing tests.

**Note:** `vitest.config.ts` includes `tests/**/*.test.ts`, so `npm test` and `npm run check` will now be red until these findings are fixed or the review folder is excluded.

### Observed but not given a dedicated failing test (all Low)

- **N-1:** `DynamoStore.replace` deletes then puts, non-atomically (`dynamo.ts:87-107`). Two cold Lambda instances racing `ensureSeed` could delete an event that was appended in between. `replace` is otherwise only used on fresh or dead sandbox ids.
- **N-2:** In SQLite, `BEGIN IMMEDIATE` sits outside the `try` (`sqlite.ts:55`). `SQLITE_BUSY` (multi-process) surfaces as a raw error instead of `ConcurrencyError`, so there is no retry.
- **N-3:** `authFromEnv` splits on `=` (`auth.ts:40`), so base64 tokens with padding make boot throw. It fails closed.
- **N-4:** `independence_report.since` is an unvalidated string compared lexicographically against UTC ISO times. A local date like "2026-10-17" includes the previous evening in LA, and garbage input silently returns zero runs.
- **N-5:** `set_step_level` to the *current* level still wipes the streaks (progress lost), yet it is annotated `destructiveHint: false, idempotentHint: true`.
- **N-6:** The `my_progress` speech "Every time you do a step without help, I'll need to say less" overstates the policy: it takes `fadeAfter` runs in a row.
- **N-7:** `resumeSpeech` "You've done N of M" counts skipped steps as done.
- **N-8:** Stale runs (more than 3 h) stay `active`. `step_done` still accepts them and counts the outcome, which revives them. Stale runs of *other* routines are never closed.
- **N-9:** Replay `day: i + 1` numbers runs, not days, and the routine `morning` is hard-coded.
- **N-10:** Reason strings and spoken times are computed with `SCAFFOLD_TZ` and the Node ICU at projection time. "Byte-identical replay" holds only for the same TZ and ICU.
- **N-11:** `/api/debug/metrics` and `/api/info` are unauthenticated. They leak only small amounts of data.
- **N-12:** Help followed by a skip (or a late drop) records no aided outcome, although `need_help` says help "informs future support levels".

## Checked and fine

- **Role scoping of tools.** A fresh `McpServer` is built per request from the token's actor. A learner cannot list or call coach tools, and a coach cannot call `decide_suggestion` or the run tools. `personId` always comes from the token; no tool takes a person id.
- **Token handling.** Sandbox tokens are 144-bit random values. Lookup is through a Map, so timing is not exploitable. The `Bearer` regex cannot backtrack badly, because header values cannot contain line terminators. An invalid token gets a JSON-RPC 401 with no `WWW-Authenticate`, on `/mcp`, `/mcp-json`, `/api/debug/events` and `/api/demo/replay`. Duplicate `Authorization` headers are rejected with 400 and do not cause actor confusion. `toNodeHandler` reads `req.headers`, so the factory sees the same token that `requireActor` checked.
- **Per-person lock in `ScaffoldService.execute`.** Calls are FIFO, a thrown `decide` releases the lock, and the map entry is removed when idle. There is no deadlock, because there is no re-entrancy, and no unbounded growth. This was verified by a probe.
- **`step_done` idempotency.** It is keyed by `run_id/step_id`. Concurrent duplicates advance exactly one step (the existing test holds). Bulk keys `…#stepId` cannot collide, because ids cannot contain `/` or `#`. A retry naming a bulk-completed step is reported as a duplicate.
- **Fading.** At most one level change per completion, and a level is never skipped. Support is added back only after `supportAfter` consecutive aided runs. `needsAttention` is set and cleared consistently. A version bump keeps the stats per step id, by design.
- **Concurrency checks in the stores.** In SQLite, `BEGIN IMMEDIATE` plus the `MAX(seq)` check plus the PK is atomic, because `node:sqlite` is synchronous inside the transaction. In DynamoDB, `attribute_not_exists(pk)` on a pk+seq table is evaluated against the item with the full key, so it correctly detects "seq N+1 already taken" (but see R-22). Query paging uses `ConsistentRead`.
- **`zonedToUtc` and `localYmd`.** They are correct across both 2026 LA DST transitions for 07:xx times, and for IST and Lord Howe. A nonexistent 02:30 maps to 01:30 PST, and an ambiguous 01:30 maps to the first occurrence. Both are acceptable.
- **Seed determinism.** It uses a fixed mulberry32 seed and deterministic ids, and the seeded levels come from the real engine commands.
- **Output schemas.** Every tool's success path produces `structuredContent` that matches its `outputSchema`; the SDK validates this server-side. Error paths return `isError` without `structuredContent`, and the SDK correctly skips validation.
- **Stateless transport.** `GET` and `DELETE /mcp` return a 405 JSON-RPC error, which is allowed for stateless servers. `MCP-Protocol-Version` is validated on both `/mcp` and `/mcp-json` (400). Locally, Host and Origin validation are on for `127.0.0.1`.
- **`ui://` resources.** These serve fixed files keyed by a constant map, so there is no path traversal. `express.static` and `sendFile` use fixed roots. There are no outbound requests with user-controlled URLs, so there is no SSRF.
- **Body and input bounds.** The JSON body limit is 100 kb. Routine text is bounded by zod (15 steps, 400/200/60 characters). The regexes in `validate.ts` and `findRoutine` are linear.
- **Tool annotations.** They match behaviour, apart from N-5. `start_routine` is effectively idempotent: a repeat resumes the run.

## Resolution (2026-10-17 22:16 IST; re-verified at release)
All 27 findings (R-01 to R-27) were fixed in commit `6ff1e5f`. Every test in `tests/review/` **passes now**. Where a fix changed the design, the test was adapted so its intent is kept:
- **R-07 and R-10:** the in-memory `SandboxRegistry` was replaced by stateless HMAC sandbox tokens and a rate limiter that runs before any write. Demo clocks are now stored in each sandbox's own event stream. The cap and sweep tests now cover the limiter, token expiry, forged tokens and store expiry.
- **R-08:** `/api/debug/events` now needs an explicit token. Learner tokens get coach free text redacted.
- **R-19 and R-27:** the schema now rejects degenerate aliases and ids that start with a digit. The tests check that, and also check that the matcher and default selection stay safe if such data reaches the log another way.
- **R-01 and R-04:** the Lambda tests send a bearer token, because public deployments now default to `SCAFFOLD_ANONYMOUS=none`.

Of the N-items, these were also addressed:
- N-2: SQLITE_BUSY now maps to ConcurrencyError.
- N-3: tokens split on the first `=`.
- N-5: setting a step to its current level keeps the streaks.
- N-6: the progress wording is fixed.
- N-7: "done" counts exclude skipped steps.
- N-12: help followed by a skip counts as aided.

Still open, and documented as Low:
- N-1: non-atomic DynamoDB `replace`, used only for seeding.
- N-4: the `since` parameter is a string.
- N-8: stale runs stay `active`.
- N-9: replay numbers runs as "days".
- N-10: replay is deterministic only for a given TZ and ICU.
- N-11: `/api/debug/metrics` and `/api/info` are unauthenticated.
