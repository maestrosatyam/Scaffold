## Event schema
Every event has `seq` (per person, gap-free, starting at 1), `at` (ISO-8601), `actorId` and an optional `seeded`.

| type | fields | projection effect |
|---|---|---|
| `person.registered` | personId, displayName, coachIds | identity and coach grants |
| `routine.published` | routine, version, proposalId? | current version; version history; stats initialised at `full` for new step ids |
| `change.proposed` | proposalId, routine, baseVersion, note, proposedBy | pending proposal |
| `change.decided` | proposalId, decision | proposal status |
| `run.started` | runId, routineId, version, device | run with each step's `baseLevel` = current stats level |
| `step.helped` | runId, stepId, from, to | the run-local level rises one rung; `helps++` |
| `step.completed` | runId, stepId, idempotencyKey, bulk? | marks the step done, then **applies the fading policy** to that step's stats |
| `step.skipped` | runId, stepId, reason (`late` / `asked`) | marks the step skipped; resets the unaided streak; neither aided nor unaided |
| `run.resumed` | runId, device | adds the device; updates last activity |
| `run.finished` / `run.abandoned` | runId (+reason) | run status |
| `level.set` | routineId, stepId, level, reason | coach override; resets streaks; `coach-set` change |

## Fading policy (`applyOutcome`)
```
outcome := helps > 0 ? aided : unaided          (per step completion)
unaided: aidedStreak := 0 (reset ids if switching);  unaidedStreak++
         if unaidedStreak ≥ fadeAfter ∧ level ≠ independent → level := fadeOne(level),
            record LevelChange{cause: faded, reason, evidenceRunIds}, clear needsAttention
aided:   unaidedStreak := 0 (reset ids if switching); aidedStreak++
         if aidedStreak ≥ supportAfter ∧ level ≠ full → level := supportOne(level),
            record LevelChange{cause: support-added}, needsAttention := true
```

**Invariants** (property-tested over 200 random policies × 40 outcomes each):
- The level always stays in LEVELS.
- The level changes by at most one rung per outcome.
- A change is recorded exactly when the level changes, and its `from` equals the prior level.

## Speech templates (`core/speech.ts`)
| Situation | Template |
|---|---|
| Step at `full` | `Step i of n. <full prompt>` |
| Step at `partial` / `cue` | `<prompt>` |
| Step at `independent` | silence. The card shows "You've got this". `start_routine` says `Okay, <routine>. I'm here if you need me.` |
| Finish | `Nice, you're done at <h:mm AM>.` + `All n steps on your own.` or `k of n steps on your own.` + an announcement of any fades this run caused |
| Help at maximum support | `<full prompt> That's every detail I have for this step. Take your time, or say skip.` |

## Concurrency
- **In process.** `execute()` chains a promise per person, so commands for one person are serialised. The lock entry is removed once the chain drains.
- **Across processes.** `store.append(events, expectedLastSeq)`:
  - SQLite checks `MAX(seq)` inside `BEGIN IMMEDIATE`, and the primary key enforces it.
  - DynamoDB writes each new `(pk, seq)` item with `attribute_not_exists(pk)` in one transaction, so a taken sequence number cancels the whole append.
  - On `ConcurrencyError` the service drops its cache, re-reads and re-decides (commands are pure), for up to 5 attempts.

## Tool contract notes (Alexa+ functional requirements)
- **Stable ids for chaining.** Every result carries `run.run_id` and `step.step_id`, and step-mutating tools accept them.
- **Retry safety.** `step_done` is idempotent per `(run_id, step_id)`; a retried call returns `duplicate: true` and the unchanged current step.
- **Errors.** `DomainError` → `isError: true` with a short voice-friendly message. Input-validation errors come from the SDK's zod validation.
- **Verbatim speech.** The `speech` description says "Say this to the user exactly as written". Server `instructions` repeat the rule and the intent mapping.
- **No IDs in speech.** At most five options are offered in fallbacks (router).
